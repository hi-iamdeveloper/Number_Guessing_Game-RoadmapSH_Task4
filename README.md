# Number Guessing Game — консольная игра «Угадай число»

Java-приложение, в котором компьютер загадывает число от 1 до 100, а игрок пытается
его угадать за ограниченное число попыток. Сложность определяет количество попыток.
Результаты сохраняются в таблицу лидеров с именами игроков.

![Java](https://img.shields.io/badge/Java-17+-blue)

---

## Возможности

- 🎮 **Три уровня сложности** — Легкая (10 попыток), Средняя (5), Сложная (3).
- 🎲 **Случайное число** от 1 до 100 в каждой партии.
- 🔼🔽 **Подсказки «больше/меньше»** после каждой неудачной догадки.
- 📊 **Учёт попыток** — в конце видно, за сколько ходов удалось угадать.
- 💡 **Система подсказок** — ввод `0` даёт подсказку по чётности числа.
- 🏆 **Таблица лидеров** — топ-3 результата по каждой сложности.
- 🔁 **Повторные партии** — можно играть сколько угодно, не выходя из программы.
- ✅ **Валидация ввода** — буквы вместо чисел не ломают игру.
- 🧭 **Главное меню** — начать игру, посмотреть лидерборд, выйти.

## Структура проекта

| Класс | Назначение |
|---|---|
| `Main` | Точка входа: создаёт `Scanner`, показывает приветствие, запускает `Menu` |
| `Menu` | Главное меню, цикл партий, обработка выбора игрока |
| `Game` | Логика одной партии: загадывание, чтение догадок, подсказки |
| `Difficulty` | Enum сложностей с числом попыток и названием |
| `Player` | Одно результат игрока: имя, попытки, сложность |
| `LeaderBoard` | Хранение и вывод топ-3 результатов по каждой сложности |

### Ответственности классов

| Класс | Что делает | Чего **не** делает |
|---|---|---|
| `Main` | Создаёт `Scanner`, запускает меню | Игровая логика |
| `Menu` | Управляет меню и циклом партий | Не знает правил игры |
| `Game` | Играет одну партию, читает ввод, даёт подсказки | Не знает про меню |
| `Difficulty` | Хранит число попыток и название | Не знает про игру |
| `Player` | Хранит имя, попытки, сложность | Не сортирует себя |
| `LeaderBoard` | Хранит результаты, выводит топ-3 | Не читает ввод |

## Ключевые решения

### 1. `EnumMap` для лидерборда

```java
private static final Map<Difficulty, List<Player>> results = new EnumMap<>(Difficulty.class);
```

Почему именно `EnumMap`, а не `HashMap`:

- **Быстрее** — внутри массив по ординалу enum, без хеширования.
- **Порядок итерации** — `EASY, MEDIUM, HARD`, как объявлено в enum. У `HashMap` порядок случайный, и сложности прыгали бы при каждом выводе.
- **Не принимает `null`-ключ** — `Difficulty` всегда корректный.

### 2. `static`-блок инициализации

```java
static {
    for (Difficulty d : Difficulty.values()) {
        results.put(d, new ArrayList<>());
    }
}
```

Выполняется один раз при загрузке класса. Создаёт пустой список для каждой сложности.
Без этого `results.get(HARD)` вернул бы `null` и первый `submit` упал бы с
`NullPointerException`.

### 3. Единая точка чтения чисел

```java
public static int readInt(Scanner scanner, String prompt) {
    while (true) {
        System.out.print(prompt);
        if (scanner.hasNextInt()) return scanner.nextInt();
        System.out.println("Нужно вводить число!");
        scanner.next();
    }
}
```

Один метод — один способ защитить ввод. Все места, где нужно число от игрока, зовут его.

Почему `hasNextInt()` вместо `try/catch`:

- Читается проще — проверяем **до** чтения, а не ловим ошибку после.
- Не оставляет мусора в буфере — при ошибке явно вызываем `scanner.next()`.
- Не кидает исключений — работает предсказуемо.

### 4. Подсказка без списания попытки

```java
int attempt = 1;
while (attempt <= attempts) {
    int guess = readInt(scanner, "Твоя догадка (0 — подсказка): ");

    if (guess == 0) {
        ...
        continue;   // attempt НЕ увеличиваем
    }
    ...
    attempt++;
}
```

`continue` перескакивает на следующую итерацию, **минуя `attempt++`**. Попытка не сгорает.
`attempt++` стоит в конце тела — увеличивается только после реальной неудачной догадки.

Если было бы `for (int i = 0; i < attempts; i++)`, пришлось бы писать `i--` для компенсации —
костыль. `while` честнее отражает логику.

### 5. Сортировка при выводе, а не при добавлении

```java
list.sort(Comparator.comparingInt(Player::getAttempts));
```

Список хранится в порядке добавления. Сортируется каждый раз при `print()`. Почему так:

- **Дешевле** — сортировка нужна только для отображения.
- **Гибко** — завтра можно выводить в другом порядке, не меняя хранилище.
- **Просто** — добавление — это всегда `list.add(...)`, никаких условий.

Для 10–100 записей сортировка на лету — мгновенно.

### 6. `Math.min` для топ-3

```java
int limit = Math.min(3, list.size());
for (int i = 0; i < limit; i++) {
```

Без `Math.min` цикл `for (int i = 0; i < 3; i++)` при списке из 1 элемента кинет
`IndexOutOfBoundsException` на второй итерации.

### 7. Разделение обязанностей между `Menu` и `Game`

`Menu` управляет меню и циклом партий. `Game` играет **одну** партию и возвращается.
`Menu` не зовёт сам себя из глубины `Game` — иначе стек рос бы с каждой партией.

Поток управления:

```
main → Menu.printMenu → Menu.playRounds → Game.printGameMenu → Game.startGame
                                              ↑                       ↓
                                              └────────── return ─────┘
```

Каждый метод возвращает управление вызвавшему. Решение «что дальше» принимает `Menu`,
а не `Game`.

## Методы `LeaderBoard`

| Метод | Что делает |
|---|---|
| `submit(String, int, Difficulty)` | Добавляет результат игрока в нужную сложность |
| `print()` | Выводит топ-3 по каждой сложности, отсортированные по попыткам |

## Методы `Game`

| Метод | Что делает |
|---|---|
| `printGameMenu(Scanner)` | Показывает меню сложностей, возвращает выбранную `Difficulty` |
| `startGame(Difficulty, Scanner)` | Играет одну партию до победы или конца попыток |
| `readInt(Scanner, String)` | Читает число с защитой от неверного ввода |

### Пример использования

```java
Scanner scanner = new Scanner(System.in);
Menu.printMenu(scanner);
```

Игровой процесс:

```
Меню:
1. Начать игру
2. Вывести список лучших результатов
3. Покинуть игру
Твой выбор: 1

Выбери сложность:
1. Легкая (10 попыток)
2. Средняя (5 попыток)
3. Сложная (3 попытки)
Твой выбор: 2

Я загадал число от 1 до 100 — угадывай!
Осталось попыток: 5
Твоя догадка (0 — подсказка): 50
Загаданное число меньше.
...
Поздравляю! Ты угадал за 3 попыток.
Введи своё имя: Иван
```

## Технологии

- **Java 17+** — switch-выражения.
- **Коллекции:**
  - `EnumMap` — таблица лидеров с ключом-сложностью.
  - `ArrayList` — список результатов внутри каждой сложности.
  - `List`, `Map` — интерфейсы, чтобы код не зависел от конкретной реализации.
- **`java.util.Random`** — генерация чисел. Один экземпляр на класс.
- **`java.util.Comparator`** — сортировка результатов.
- **`switch`-выражения** — для выбора сложности.
